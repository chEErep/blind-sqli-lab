# Как запустить и проверить стенд (для Windows, с нуля)

Ничего кроме **Docker Desktop** ставить не нужно. Python и MySQL уже внутри
контейнеров — Docker сам их скачает.

## Шаг 1. Поставить Docker Desktop
1. Скачай установщик: https://www.docker.com/products/docker-desktop/
   (кнопка «Download for Windows»).
2. Запусти `Docker Desktop Installer.exe`. Галочку **«Use WSL 2 instead of Hyper-V»**
   оставь включённой. Соглашайся со всем, в конце перезагрузи компьютер, если попросит.
3. Если при первом запуске Docker напишет, что нужен **WSL 2**:
   открой **PowerShell от имени администратора**, выполни
   ```
   wsl --install
   ```
   и перезагрузись.
4. Запусти **Docker Desktop** (иконка кита). Подожди, пока внизу слева
   статус станет **«Engine running»** (зелёный). Docker должен быть запущен,
   когда выполняешь команды ниже.

> Если Docker не стартует и ругается на виртуализацию — её нужно включить
> в BIOS/UEFI (обычно уже включена). Это редкий случай.

## Шаг 2. Запустить проект
1. Открой папку `D:\Практика\blind-sqli-lab` в Проводнике.
2. Кликни в адресную строку Проводника, набери `powershell` и нажми Enter —
   откроется PowerShell прямо в этой папке.
3. Выполни:
   ```
   docker compose up --build
   ```
4. Первый раз Docker качает образы (MySQL, Python) — пара минут, это нормально.
   Когда в логах появятся строки вроде `sqli-backend ... Running` и поток логов
   без ошибок — всё поднялось.

## Шаг 3. Проверить, что работает
1. Открой браузер → http://localhost:8000 — откроется страница входа.
2. Войди: **alice / alice123** → попадёшь в личный кабинет.
   Значит фронт + бэк + база работают вместе. ✅
3. Проверь базу: http://localhost:8000/health → должно показать
   `{"status": "ok", "safe_mode": true}`.
4. Нажми «Забыли пароль?», введи `alice@demo.local` → увидишь нейтральное
   сообщение «если такой email зарегистрирован, мы отправили ссылку».
   Оно одинаковое всегда — это и есть «слепота» уязвимости.

## Шаг 4. Остановить
- В окне PowerShell нажми **Ctrl+C**.
- Чтобы погасить и стереть данные базы:
  ```
  docker compose down -v
  ```

## Позже: как проверить саму уязвимость
Это уже после того, как впишешь уязвимый запрос (`find_user_by_email_vulnerable`
в `app.py`) и поставишь `SAFE_MODE: "false"` в `docker-compose.yml`, затем
пересоберёшь (`docker compose up --build`).

Быстрая проверка без Burp — прямо в PowerShell засечь время ответа:
```
Measure-Command { curl.exe -s -X POST "http://localhost:8000/forgot" --data-urlencode "email=x' OR (SELECT SLEEP(5))-- -" }
```
Если заняло ~5 секунд — инъекция работает. В безопасном режиме (`SAFE_MODE=true`)
тот же запрос отвечает мгновенно. Полную демонстрацию через Burp разберём отдельно.
